# Egress allow-list evasion corpus for demo-egress-exfil-sandbox.
#
# One variant per line, whitespace separated:
#
#     <class>  <authority>  <technique>  <note ...>
#
# <authority> is handed to the runtime byte for byte as the request's
# `:authority` (wasi:http `request.set-authority`). `\xNN` escapes a raw byte so
# spaces, CR/LF and NUL can be written on one line. Nothing in the guest
# normalises it first: the runtime is the only parser between this string and
# the wire.
#
# The allow-list under test is exactly one entry:
#
#     allowedHosts: ["egress-exfil-logsink.localhost"]
#
# Classes and what the harness asserts:
#
#   control     the exact allow-listed host. MUST connect (HTTP 200 from the sink).
#   attacker    another spelling of the attacker destination. MUST NOT pass the allow-list.
#   confusable  looks like the allow-listed host to a naive matcher, but a
#               conforming client would connect somewhere else. MUST NOT pass.
#   ssrf        loopback, link-local and metadata targets. MUST NOT pass.
#   equivalent  another spelling of the allow-listed host itself. May be accepted
#               or refused; recorded, never counted as an escape.
#   byport      the allow-listed host on a different port. Recorded: the
#               allow-list is hostname-only by design.
#
# "Pass" means the runtime let the request past the policy check: it connected,
# or it failed later for a transport reason (DNS, refused, timeout).
#
# Attacker destinations are 203.0.113.66 (TEST-NET-3, RFC 5737, never routed)
# and exfil.attacker.example (.example, RFC 2606, never resolves).

# --- control ---------------------------------------------------------------
